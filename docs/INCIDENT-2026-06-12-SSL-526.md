# Incident — 2026-06-12 · Cloudflare 526 (Invalid SSL certificate)

**Status**: resolved · **Downtime**: enrola.shop + api unreachable behind
Cloudflare from ~2026-06-11 13:17 UTC (origin cert expiry) until
2026-06-12 ~21:01 UTC (renewal succeeded).

## Symptom

All `enrola.shop` hosts (storefront, api, www) returned Cloudflare
**error 526 — Invalid SSL certificate**. Browser → Cloudflare: OK.
Cloudflare → origin (VPS): cert validation failed.

## Root cause

The reverse proxy for the whole VPS is **traefik from the n8n stack**
(`n8n-traefik-1`, compose at `/docker/n8n/docker-compose.yml` on the VPS —
*not in this repo*). Its Let's Encrypt resolver used the **TLS-ALPN-01**
challenge (`tlschallenge=true`).

TLS-ALPN-01 requires Let's Encrypt to open a TLS connection directly to
port 443 of the origin and negotiate the `acme-tls/1` ALPN protocol.
Once the DNS records were proxied through Cloudflare (orange cloud),
Let's Encrypt reached **Cloudflare's edge** instead of the origin, the
ALPN negotiation failed, and every renewal returned:

```
403 urn:ietf:params:acme:error:unauthorized ::
Cannot negotiate ALPN protocol "acme-tls/1" for tls-alpn-01 challenge
```

The original certs were issued **2026-03-13** (before the proxy was
enabled) and expired **2026-06-11**. Renewals had been failing silently
for ~2 months — the expiry was the first visible symptom. All domains on
the VPS were affected (enrola.shop, api, www, panel, linkfuel.click,
oficina.linkfuel.click, hechoxrefugiados.com).

## Fix (emergency bypass, applied directly on the VPS)

Switched the ACME challenge to **HTTP-01**, which works behind
Cloudflare because port 80 is proxied through to the origin and traefik
answers `/.well-known/acme-challenge/*` before applying its
web→websecure redirect.

In `/docker/n8n/docker-compose.yml` (backup saved next to it as
`docker-compose.yml.bak-526-*`):

```diff
-      - "--certificatesresolvers.mytlschallenge.acme.tlschallenge=true"
+      - "--certificatesresolvers.mytlschallenge.acme.httpchallenge=true"
+      - "--certificatesresolvers.mytlschallenge.acme.httpchallenge.entrypoint=web"
```

The resolver keeps its (now misnomer) name `mytlschallenge` so no
service labels had to change. Then `docker compose up -d traefik`.
All certs re-issued within a minute (valid until 2026-09-10).

## Watch-outs / follow-ups

- **Do not enable Cloudflare "Always Use HTTPS"** (or any edge redirect
  / WAF rule that intercepts `http://*/.well-known/acme-challenge/*`) —
  it would break HTTP-01 renewals the same silent way. If a redirect is
  ever needed, add a Cloudflare configuration rule exempting the ACME
  path first.
- Next renewal window: ~30 days before 2026-09-10 (early August). If it
  fails, `docker logs n8n-traefik-1 | grep -i acme` on the VPS.
- Longer-term option: DNS-01 with a Cloudflare API token (immune to
  proxy/redirect settings), or Cloudflare Origin CA certs. Not done now
  to keep the emergency change minimal.
- Consider an uptime check that hits `https://enrola.shop` from outside
  (the 526 was user-reported, not alerted).
